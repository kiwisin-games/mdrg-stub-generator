# MDRG LuaLS Addon

LuaLS/Sumneko definitions for the Lua/MoonSharp modding API exposed by **MDRG**.

This addon gives mod authors typed autocomplete, hover information and diagnostics for MDRG Lua scripts. It is generated from the game's exposed documentation, curated C# dump indexes, generated Lua usage evidence and runtime probe reports.

> Current release target: **MDRG game version 96.7**

## Downloads

Download the latest packaged addon from:

[github.com/kiwisin-games/mdrg-stub-generator/releases](https://github.com/kiwisin-games/mdrg-stub-generator/releases)

Use the release asset named like:

```text
mdrg-luals-addon.zip
```

GitHub also provides automatic source archives, but those are not the recommended install package. The release asset is the clean addon bundle.

## What This Is

This repository maintains a reproducible LuaLS addon for MDRG mod development.

It provides definitions for:

- MDRG globals and runtime helpers.
- `ModUtilities`, `GameUtilities`, `GameVariables` and related managers.
- `Item`, `ItemPrefab`, shop, slot, edible, fishing and equipment APIs.
- Story, condition, save, personality module and dialogue APIs.
- UI/browser/runtime legacy symbols observed in game scripts.
- Unity/Fungus/MoonSharp-facing types that are exposed to Lua.
- LuaPatch safe `io` stubs from `extern/mdrg_safe_io.d.lua`.

The addon is documentation and editor metadata only. It does not implement game behavior.

## Installation

1. Download `mdrg-luals-addon.zip` from the releases page.
2. Extract it into your LuaLS addon directory.
3. Keep the extracted structure intact:

```text
mdrg/
  config.json
  info.json
  library/
  README.md
```

4. Enable the addon in LuaLS/Sumneko, or point `workspace.userThirdParty` at the parent directory containing the extracted `mdrg/` folder.

For VS Code users, the target is usually the addon manager path used by LuaLS:

```text
%APPDATA%\Code\User\globalStorage\sumneko.lua\addonManager\addons\
```

## Package Contents

The distributed ZIP contains only the files needed by LuaLS:

- `config.json`
- `info.json`
- `README.md`
- `library/*.d.lua`
- `examples/test.lua`
- tracked external stubs from `extern/*.d.lua`, copied into `library/`

The package intentionally excludes raw dumps, research data, runtime reports, tools and debug mods.

## Repository Layout

Important tracked inputs:

- `docs.txt`: authoritative source for exposed classes, members, signatures and raw C# type names.
- `data/*.json`: curated indexes derived from C# dumps, generated Lua scripts, Unity snippets and runtime probes.
- `data/runtime_callback_evidence.json`: reviewed callback/runtime evidence extracted from local `probe/runtime_test_*` reports.
- `documented_functions.md`: reviewed documentation snippets imported only when aligned with `docs.txt`.
- `extern/*.d.lua`: external/plugin stubs copied into `library/` after generation.
- `luas/`: compact tracked research corpus of Lua generated by the game.

Generated or packaged outputs:

- `library/*.d.lua`: generated LuaCATS definitions consumed by LuaLS.
- `dist/mdrg-luals-addon.zip`: clean release package created by `tools/package_addon.py`.
- `analysis/*.md`: audit, validation and evidence reports.

Local research inputs, ignored by Git:

- `dump/`: Cpp2IL `diffable-cs` output used for structure, inheritance and signatures.
- `rawdump/`: verbose/decompiled output used as auxiliary semantic evidence.
- `probe/runtime_test_*/`: local runtime callback reports.
- `examples/mods_mixed.lua`: large mixed mod research input.

## Development Workflow

Common commands:

```powershell
python .\tools\dev.py check
python .\tools\dev.py generate
python .\tools\dev.py index
python .\tools\dev.py sync
python .\tools\dev.py validate
python .\tools\dev.py clean
```

Use `dev.py generate` to regenerate stubs from `docs.txt` and committed curated indexes. Use `dev.py index` only after replacing local research inputs such as `dump/`, `rawdump/`, `luas/` or Unity exports.

Build the release ZIP with:

```powershell
python .\tools\package_addon.py
```

The package script validates the addon first, then writes:

```text
dist/mdrg-luals-addon.zip
dist/package_report.md
```

## Runtime Evidence Workflow

This project includes optional probes for collecting runtime evidence from the game:

- `examples/mdrg_env_probe.lua`: broad read-only runtime environment probe.
- `examples/mdrg_callback_context_probe.lua`: callback/lifetime probe helper.
- `examples/callback_debug_mod_real/`: opt-in debug mod for callback testing.

The probes are disabled by default and are intended for disposable test saves.

After collecting callback reports under `probe/runtime_test_*`, run:

```powershell
python .\tools\build_runtime_callback_evidence.py --root probe
python .\tools\summarize_runtime_tests.py --root probe
python .\tools\catalog_lua_callbacks.py
```

Runtime evidence is review material. It does not automatically create APIs or edit stubs.

## Quality Policy

The project follows conservative generation rules:

- `docs.txt` decides whether a public symbol exists.
- `data/*.json` stores curated evidence needed for reproducible generation.
- `library/*.d.lua` should not be edited manually.
- Unknown or ambiguous types stay broad, often as `any`, until safer evidence exists.
- Callback reports preserve runtime context and are not generalized blindly.
- Aliases for observed strings keep `|string` fallbacks when custom values are possible.
- `ValueTuple` and `KeyValuePair` stay as `table`/`table[]`; fields are not invented.

LuaLS is optional for local validation. If `lua-language-server` is not available in `PATH`, tools should warn rather than fail solely for that reason.
